# Как сделать своё расширение для AxmatCord

**Что это за документ.** Практическое руководство для внешних разработчиков: как написать, собрать, упаковать и опубликовать плагин или тему для AxmatCord — неофициального нативного клиента Discord (Rust/egui). Документ самодостаточен: собран по фактическому состоянию SDK и кода загрузки расширений.

**Область применения и предпосылки.** ABI расширений версии 1 (`api_version: 1`), крейт SDK `axmatcord-extension-sdk` 0.1.0. Возможности, помеченные **Preview**, заявлены как предварительные: хост без их поддержки отклонит манифест ещё при установке. Базовые знания Rust и командной строки предполагаются; аккаунт Discord и учётные данные для разработки не нужны — всё проверяется на синтетических данных.

**Версия документа:** 1.0.0 от 2026-11-16.

## 1. Что такое расширения

Расширение — локальный, опциональный инструмент для нативного клиента. Два вида:

- **Плагин** (`"kind": "plugin"`) — Rust-код, скомпилированный в WebAssembly. Хост передаёт обработчику JSON, обработчик возвращает JSON; хост рендерит нативные элементы управления или показывает предложение операции. Никакого постоянного процесса, сетевого соединения или колбэка отрисовки у плагина нет.
- **Тема** (`"kind": "theme"`) — декларативный JSON-пакет (цвета, типографика, отступы, необязательный фон). Wasm-модуля нет, код не исполняется.

### Модель безопасности

- Каждый вызов обработчика получает **свежий экземпляр Wasm** на фоновом worker'е; локальные переменные между вызовами не живут. Состояние хранят через capability `storage`.
- Плагин **не может** напрямую вызывать Discord, читать учётные данные, открывать файлы или выполнять сетевые запросы. Никакого WASI и host-импортов в Wasm.
- Доступ к данным даётся **capability** — именованным разрешением, которое пользователь подтверждает отдельно для каждого расширения. Поддерживаемая хостом capability ≠ выданная: пользователь может её не дать.
- Изменения приложения (отправка сообщения, переход в канал, смена настроек) — только **предложения (effects)**: хост показывает операцию целиком и ждёт кнопки **Apply**, перед нажатием перепроверяет плагин, гранты, контекст и нативные права.
- Снапшоты данных читают только уже загруженное состояние; чтение не вызывает сетевых запросов и не догружает историю.
- Снапшоты не содержат токены, удалённый/ephemeral текст, байты вложений, URL медиа или сырые Gateway-данные.
- Хранилище плагина — обычные локальные данные, не зашифрованные клиентом. Не храните там учётные данные.

### Поверхности (surfaces)

Действие (action) из манифеста объявляет **поверхность** — когда и в каком контексте хост его вызывает:

| Surface | Когда вызывается | Обязательная capability |
| --- | --- | --- |
| `panel` | Пользователь открыл инструмент или нажал кнопку панели | нет (данные — через отдельные гранты) |
| `message` | Пользователь выбрал действие сообщения | `selected_message` |
| `composer` | Пользователь выбрал действие черновика | `composer` |
| `activation` | Включение плагина или загрузка аккаунта | нет; **не более одной** на плагин |
| `message_event` | Принятое живое изменение сообщения | `message_events`; **не более одной** |
| `app_event` | Поддерживаемое изменение приложения | `app_events`; **не более одной** |
| `tick` (Preview) | Расписание хоста, пока включён и подписан | `appearance`; **не более одной** |
| `user` / `channel` / `server` / `role` | Пункт контекстного меню пользователя/канала/сервера/роли | `context_menus` |

Capability сама по себе не регистрирует обработчик: для `message_event`, `app_event` и `tick` нужно объявить и соответствующее действие.

## 2. Установка инструментов

Нужны:

1. **Rust через rustup** — проект закрепляет toolchain (`rust-toolchain.toml`, канал 1.99.1); при первом запуске cargo из checkout'а rustup сам установит нужную версию.
2. **Цель сборки Wasm** — `wasm32-unknown-unknown` (так собираются все примеры и плагины проекта; это единственная задокументированная цель).
3. **Python 3** — только как инструмент упаковки автора; конечным пользователям Python не нужен.

Проверка из корня проекта (или вашей копии SDK):

```powershell
rustup show active-toolchain
python --version
rustup target add wasm32-unknown-unknown
```

Первая команда должна показать закреплённый toolchain (если его нет — rustup предложит установить), вторая — Python 3.

Если вы работаете вне checkout'а проекта, скопируйте к себе крейт SDK (`axmatcord-extension-sdk`), упаковщик `pack.py` и workspace-файлы (`Cargo.toml` + `Cargo.lock`) из расширений проекта; в скопированном `Cargo.toml` добавьте `"sdk"` в `members` и зависимость `axmatcord-extension-sdk = { path = "sdk" }`, после чего один раз выполните `cargo check --workspace`, чтобы обновить lockfile. Коммитьте `Cargo.lock` и собирайте с `--locked` — это даёт воспроизводимую сборку.

## 3. Минимальный плагин: пошагово

Соберём **Hello Context** — панель, показывающую выбранный канал. Шаги: манифест → обработчик → сборка → проверка → упаковка → импорт. Манифест объявляет разрешения и точки входа, но не содержит код плагина.

### Шаг 1. Манифест

`manifest.json`:

```json
{
  "api_version": 1,
  "id": "hello-context",
  "name": "Hello Context",
  "version": "1.0.0",
  "author": "Your name",
  "license": "MIT",
  "source": "https://example.org/hello-context",
  "kind": "plugin",
  "capabilities": ["app_context"],
  "actions": [
    {"id": "show", "label": "Show current channel", "surface": "panel"}
  ]
}
```

Перед публикацией замените автора и ссылку на источник.

| Поле | Обязательное | Тип | Правила |
| --- | --- | --- | --- |
| `api_version` | да | integer | только `1` — версия контракта Wasm/JSON. Не означает, что все capabilities есть в старом хосте. |
| `id` | да | string | стабильный уникальный идентификатор; строчные ASCII-буквы, цифры и дефис, начинается с буквы или цифры, ≤64 байт. Зарезервированы Windows-имена устройств (`con`, `nul` и т.п.). Сохраняйте id между обновлениями — на нём держатся установка, гранты и хранилище. |
| `name` | да | string | отображаемое имя: непустое, ≤128 UTF-8 байт, без управляющих символов. |
| `version` | да | string | метка выпуска, например `1.0.0`; семвер не принуждается. Ограничения как у `name`. |
| `author` | да | string | атрибуция создателя. Ограничения как у `name`. |
| `license` | да | string | метка лицензии; сам текст лицензии включите в исходники. Ограничения как у `name`. |
| `source` | да | string | публичная HTTPS-ссылка ≤2048 UTF-8 байт, без учётных данных в URL. Это метаданные, не исполняемый код. Для тем допустима пустая строка. |
| `kind` | да | string | `plugin` для Wasm, `theme` для декларативных тем. |
| `capabilities` | нет | string[] | только нужные разрешения; имена должны быть известны и уникальны, ≤64 объявлений (сейчас поддерживается 56 имён). Темы не объявляют capabilities. |
| `actions` | да (у плагина) | object[] | 1–16 действий с уникальными `id`. У тем действий нет. |

Ограничение размера: упаковщик и офлайн-чекер принимают манифест до 16 КиБ. Отдельный лимит манифеста внутри хоста не документирован — пакет целиком ограничен 16 МиБ.

Каждое действие:

| Поле | Тип | Правила |
| --- | --- | --- |
| `id` | string | приходит в обработчик как `input.invocation.action` (или `input.action`); кнопки панели вызывают этот же id. Те же правила, что у `id` манифеста. |
| `label` | string | отображаемое имя: непустое, ≤128 UTF-8 байт, без управляющих символов. |
| `surface` | string | когда действие запускается и какой контекст получает — см. [таблицу поверхностей](#поверхности-surfaces). |

Кросс-правила, которые проверяет хост:

- `data_events` требует `app_events`;
- `data_queries` и `action_feedback` требуют `app_events` и одно действие с поверхностью `app_event`;
- `api_proxy` — особый «connection-плагин»: только `api_proxy` + опционально `storage`, только поверхности `panel`/`activation`;
- поверхность требует свою capability (`message` → `selected_message`, `composer` → `composer`, `message_event` → `message_events`, `app_event` → `app_events`, `tick` → `appearance`, `user`/`channel`/`server`/`role` → `context_menus`);
- у темы не может быть ни capabilities, ни actions; плагин обязан иметь хотя бы одно действие.

Проверить манифест офлайн правилами хоста (нужен checkout проекта):

```powershell
cargo run --locked -p extensions --example manifest_check -- путь/к/manifest.json
```

Чекер принимает автономный JSON-манифест до 16 КиБ (не пакет), не запускает Wasm и не выдаёт права. Успешная проверка проверяет только манифест: пакет, Wasm-импорты, валидация вывода, fuel и живая совместимость — отдельные шаги. Импорт повторно валидирует манифест правилами установленного хоста: старый хост может отклонить capability, принятую новым чекером.

SDK также экспортирует типы `Manifest`, `Action`, `Surface`, `ExtensionKind`, `Capability` — можно генерировать манифест программно. Учтите: типизированное построение или успешный JSON-парсинг **не** проверяют лимиты, дубликаты и сочетания capability/surface — за этим нужен `validate`.

### Шаг 2. Обработчик

`src/lib.rs` (действие `show` соответствует манифесту выше):

```rust
use axmatcord_extension_sdk::{AppInvocation, AppOutput, Element, Output};

fn handle(input: AppInvocation) -> AppOutput {
    if input.invocation.action != "show" {
        return AppOutput::default();
    }
    let channel = input.app.as_ref()
        .and_then(|app| app.context.as_ref())
        .and_then(|context| context.channel.as_ref());
    let text = match channel {
        Some(channel) => format!("You are in {} (ID {}).", channel.name, channel.id),
        None => "No accessible channel is selected.".into(),
    };
    AppOutput {
        output: Output { panel: vec![Element::Text { text }], ..Default::default() },
        ..Default::default()
    }
}
axmatcord_extension_sdk::export!(handle);
```

Что здесь происходит:

- `input.invocation.action` определяет, какое действие манифеста вызвано; один обработчик обслуживает все действия плагина.
- `input.app` содержит выданные и доступные данные; каждый необязательный слой проверяется отдельно — отсутствие выбранного канала это нормальное состояние, а не ошибка.
- `output.panel` просит хост отрисовать текст сразу, без кнопки Apply.
- `export!` генерирует Wasm-экспорты ABI v1; сам обработчик остаётся обычным тестируемым Rust.

Полям ввода и вывода посвящён [раздел 7](#7-действия-и-события).

### Шаг 3. Сборка

Из каталога с вашим workspace (в проекте — `examples/extensions/`):

```powershell
rustup target add wasm32-unknown-unknown
cargo build --locked --release --target wasm32-unknown-unknown -p app-toolbox
```

`-p app-toolbox` — имя Cargo-пакета примера; для своего плагина укажите своё имя крейта. Результат: `target/wasm32-unknown-unknown/release/app_toolbox.wasm` (подчёркивания вместо дефисов). Если задан `CARGO_TARGET_DIR`, подставьте эту сборочную папку в путь Wasm для `pack.py` — cargo не обязан писать в локальный `target/`.

### Шаг 4. Упаковка

Пакет `.axmatcord-extension` — один JSON-файл, объединяющий манифест и байты Wasm:

```json
{"manifest": {"api_version": 1, "id": "hello-context", "...": "..."}, "wasm": [32, 0, 97, 115, 109, 1, 0, 0, 0, ...]}
```

`"wasm"` — массив чисел 0–255, то есть точное содержимое собранного `.wasm`-файла (структура проверена по коду `parse_package` и упаковщику). Неизвестные ключи пакета отклоняются; допустимы только `manifest`, `wasm`, `theme`, `background_image`, `cover_image` (последние три — для тем). Лимиты: модуль ≤4 МиБ, пакет ≤16 МиБ.

Упаковка штатным скриптом проекта:

```powershell
python pack.py manifest.json target/wasm32-unknown-unknown/release/app_toolbox.wasm packages/hello-context.axmatcord-extension
```

Скрипт печатает путь, размер в байтах и SHA-256. Опциональный флаг `--license FILE` добавляет в Wasm инертную custom-секцию `axmatcord.license` с текстом лицензии (хост игнорирует custom-секции при исполнении; сумма с модулем всё равно ≤4 МиБ). Имя файла пакета может отличаться от `manifest.id`. Скрипт никогда не скачивает и не исполняет код создателя — это сборочный инструмент автора.

### Шаг 5. Импорт и проверка

См. [раздел 4](#4-установка-и-проверка-в-клиенте). Кратко: Настройки → Расширения → Import, выдать грант `app_context`, включить, открыть карточку **Hello Context** → **Open tool** → **Show current channel**. Успех — панель показывает `You are in ... (ID ...).` или сообщение о недоступном контексте. Импорт сам по себе не выдаёт права и не исполняет плагин.

### Шаг 6. Правки

После изменения обработчика пересоберите, переупакуйте и импортируйте пакет заново, заново подтвердив гранты. Правка Rust-исходников или манифеста на диске **не** обновляет установленный модуль.

## 4. Установка и проверка в клиенте

Локальная установка возможна двумя путями:

**Релизный клиент.** Настройки → Расширения → **Import**: выбирается локальный файл `.axmatcord-extension` (JSON). Темы импортируются через Настройки → Темы. Импортированный пакет не проверен каталогом: импорт не выдаёт capabilities и не исполняет код. Включение скачивает/копирует пакет, показывает точный список capabilities и требует согласия. Отдельная пользовательская папка расширений в документации не описана — локальный путь один: Import (хранением управляет клиент).

**Демо-сборка из исходников** (рекомендуется для разработки):

```powershell
cargo run --locked -p axmatcord -- --demo
```

Демо работает на синтетических данных в ограниченном временном профиле `axmatcord-extension-demo`: умеет импортировать локальные пакеты и показывает встроенный стартовый каталог с превью, но не может скачивать каталог, превью или пакеты из сети. Аккаунт и учётные данные не нужны.

Порядок проверки каждого пакета:

1. Import пакета → манифест и модуль валидируются этим хостом; неподдерживаемые capabilities отклоняются до запуска обработчика.
2. Разрешить capabilities при включении (согласие выдаётся на каждое разрешение отдельно).
3. Открыть инструмент на карточке расширения и вызвать действия. Предложения (`effects`) показывают операцию и значения и исполняются только после **Apply**; закрытие результата ничего не делает.
4. Дляcomposer-предложений: кнопка **Apply to Draft** заменяет черновик, ничего не отправляя.

Что важно помнить о жизненном цикле:

- **Disable** немедленно перестаёт принимать результаты, удаляет скачанный пакет, временные файлы и данные расширения. Повторное включение требует заново скачать/импортировать пакет и начинается с чистыми настройками расширения.
- Гранты и данные плагина принадлежат аккаунту (исключение — узкий `api_proxy`-плагин, привязанный к устройству); выход из аккаунта инвалидирует результаты и чистит данные расширений этого аккаунта. Выбор темы — настройка устройства.
- Каталог никогда не устанавливает, не обновляет и не удаляет пакеты автоматически; обновления ручные и требуют нового согласия. Локально созданные или импортированные пакеты обновлениями каталога не заменяются.
- `Ctrl+Shift+F12` — аварийный сброс community-тем и appearance-плагинов.

## 5. Тесты, диагностика и частые ошибки

### Офлайн-тест обработчика

Обработчик остаётся обычным Rust — тестировать его можно без Wasm:

```rust
#[test]
fn missing_channel_is_handled() {
    use axmatcord_extension_sdk::{dispatch_typed, serde_json, AppOutput, Element};
    let bytes = dispatch_typed(br#"{"action":"show"}"#, handle).unwrap();
    let output: AppOutput = serde_json::from_slice(&bytes).unwrap();
    assert!(matches!(&output.output.panel[0], Element::Text { text }
        if text == "No accessible channel is selected."));
}
```

Запуск (пути — из корня проекта, для своей копии подставьте свой workspace):

```powershell
cargo test --manifest-path examples/extensions/Cargo.toml --workspace --locked
cargo clippy --manifest-path examples/extensions/Cargo.toml --workspace --all-targets --locked -- -D warnings
```

`dispatch` обслуживает `Invocation`, `dispatch_typed` — типизированные обёртки. Оба прогоняют JSON-декодирование/кодирование и лимит 256 КиБ I/O без указателей; ошибки: `InputTooLarge`, `InvalidInput`, `OutputTooLarge`, `InvalidOutput`. Пройденный нативный тест доказывает декодирование входа и ожидаемый вывод, но **не** проверяет Wasm-импорты, fuel или поведение UI — для этого нужны sandbox-проверки (в проекте — пример `sdk_check`, прогоняющий собранные модули через офлайн-хост-песочницу).

### Категории ошибок исполнения хоста

Ошибки используют фиксированные сообщения хоста: они никогда не содержат вывод плагина, текст сообщений, хранилище, сырые Wasm-строки или приватные значения вызова.

| Категория | Что делать автору |
| --- | --- |
| `Fuel` | Сократите циклы, JSON-работу или объём данных; лимит — 10 млн fuel. |
| `Memory` | Сократите аллокации; линейная память ограничена 16 МиБ. Категория покрывает и отказ аллокатора движка. |
| `Stack` | Уменьшите рекурсию и стековые аллокации. |
| `Trap` | Проверьте панику, неверный доступ к памяти, арифметические ловушки. Текст паники не раскрывается. |
| `Input` / `InputLimit` | Проверьте схему действия/входа или уменьшите данные и значения формы. |
| `Handler` | ABI вернул пустой ответ — проверьте декодирование входа и сериализацию вывода. |
| `Output` / `OutputLimit` | Проверьте JSON/ABI-буфер вывода или сократите панель/текст/хранилище. |
| `Capability` | Проверьте манифест, гранты и допустимую поверхность; повтор исполнения право не выдаёт. |
| `Module` / `Execution` | Проверьте обязательные экспорты, ограничения на импорты и требования рантайма. |
| `Invalid` / `Version` / `Limit` | Проверьте схему документа, поддерживаемую версию API или соответствующие границы. |

### Частые ошибки интеграции

| Симптом | Причина |
| --- | --- |
| Пакет не импортируется | Невалидный манифест/пакет, неподдерживаемая capability, невалидный Wasm; проверьте, что импортируете пакет, а не сырой `.wasm`. |
| Capability работает в исходниках, но клиент её отклоняет | Хост старше этой capability; `api_version: 1` не гарантирует наличие всех имён. |
| Инструмент импортирован, но не запускается | Импорт не выдаёт права и не включает плагин: подтвердите гранты и включите пакет в Настройках. |
| Приложение ведёт себя «по-старому» | Установленный пакет содержит старые скомпилированные байты: пересоберите, переупакуйте, переимпортируйте. |
| Кнопка панели отклоняется | ID кнопки не совпадает с id действия с поверхностью `panel`; ID элементов панели должны быть уникальны внутри одной панели. |
| Обработчик событий не вызывается | Объявлена capability без автоматического действия (`message_event`/`app_event`) или детальной причине не хватает грантов. |
| Эффект «не сработал» | Эффект — предложение: нужен **Apply**; для фоновых поверхностей (`activation`, `message_event`, `app_event`) effects запрещены. |
| Сохранённые значения исчезают | Каждый вызов — свежий экземпляр Wasm; сохраняйте через `storage` и возвращайте новое значение из обычного действия. |

## 7. Действия и события

### Типы входа

| Тип SDK | Для чего | Как читать действие |
| --- | --- | --- |
| `Invocation` | Инструменты сообщений, composer, панели, активация | `input.action` |
| `EventInvocation` | То же + живые события сообщений | `input.invocation.action` |
| `AppInvocation` | То же + снапшоты приложения и события приложения | `input.invocation.action` |
| `ExtendedAppInvocation` | `AppInvocation` + запросы, настройки аккаунта, папки, результаты отслеживаемых действий | `input.invocation.invocation.action` |
| `TickInvocation` | Preview-действия `tick` | `input.invocation.action` |
| `MenuInvocation` | `AppInvocation` + цель контекстного меню | `input.invocation.invocation.action` |
| `MessageActionInvocation` | `AppInvocation` + IDs сообщения, на котором выбрано `message`-действие | `input.invocation.invocation.action` |

Обёртки — Rust-удобство: **JSON на проводе плоский**, объекта `invocation` и поля `surface` не существует. Смотрите `action`.

### Общие поля входа

| Поле | Тип | Когда приходит |
| --- | --- | --- |
| `action` | string | ID действия манифеста (не его label). |
| `selected_message` | string \| null | Текст выбранного сообщения; требует `selected_message` и поверхность `message`. IDs приходят отдельно в `selected_message_ref`. |
| `composer` | string \| null | Текущий черновик для `composer`-действия; пустой черновик — `Some("")`, не `None`. |
| `storage` | string \| null | Последнее сохранённое значение плагина; требует `storage`; отсутствует, если ничего не сохранено. |
| `values` | object | Значения формы при нажатии кнопки панели: строки! Чекбокс — `"true"`/`"false"`, слайдер — десятичная строка, select — выбранная строка. ≤64 ключей, значение ≤4 КиБ. Хелперы: `value(id)`, `parse_value::<T>(id)`, `storage_json::<T>()`. |

`parse_value` возвращает `Ok(None)` для отсутствующего ввода, `Ok(Some(v))` для корректного и `Err` для кривого — проверяйте допустимые диапазоны сами. Кнопка панели начинает **новый** вызов: она получает значения формы и storage, но не наследует исходное сообщение или черновик.

Дополнительные поля (все опциональные, присутствуют при поддержке хостом и грантах): `host` (публичный каталог возможностей хоста), `message_event`, `app` (снапшот), `app_event` (причина вызова наблюдателя), `queries`, `messaging_settings`, `guild_folders`, `action_result`, `selected_message_ref`, `menu_target`, `tick_ms`.

### HostInfo: что поддерживает хост

Текущие хосты вставляют публичный каталог поддержки в каждый вызов (без гранта и аккаунтных данных). На старых хостах `host` отсутствует:

- `api_version: 1`, `sdk_revision: 1`;
- `capabilities` — 56 поддерживаемых имён capability (не грантов!);
- `app_events` — 21 поддерживаемое имя события;
- `interface_tweaks` — 9 имён тиков: `static_typing_indicator`, `plain_profiles`, `expanded_roles`, `hidden_request_counts`, `one_ping_per_direct_message`, `hidden_blocked_messages`, `hidden_profile_notes`, `large_stream_preview`, `double_click_reply_edit`.

Хелперы: `host.supports("message_content")`, `host.supports_event("typing")`, `host.supports_tweak("expanded_roles")`. Поддержка ≠ согласие; неизвестная обязательная capability всё равно отклоняется при установке.

### Поля вывода

Обрабатываемый ответ — один плоский JSON-объект ≤256 КиБ. Неизвестные поля и неверные типы отклоняются.

| Поле | Capability | Когда действует |
| --- | --- | --- |
| `replacement` | `composer` | **Apply to Draft** заменяет исходный неизменённый черновик; сообщения не отправляет. |
| `panel` | нет | Массив нативных элементов, отображается сразу для foreground-результата. Обработчики `message_event`/`app_event` обязаны вернуть пустую панель; активация панель не показывает. |
| `storage` | `storage` | Валидный foreground/событийный результат заменяет сохранённое значение. |
| `appearance` | `appearance` | Принятый результат немедленно обновляет оверлей темы плагина (включая активацию и события). |
| `interface_tweaks` | `interface_tweaks` | Результат `activation`/`panel` заменяет список тиков плагина; пустой массив выключает. |
| `preserve_deleted_messages` | `deleted_messages` (для `true`) | Только результат `activation` включает хранение удалённых сообщений. |
| `image_sharing` | `image_sharing` | Устаревшее поле совместимости; на поведение не влияет. |
| `effects` | по операции | Не более одного предложения ≤8 КиБ; исполняется только после **Apply**. |

Семантика «отсутствует/null/пусто»:

| Поле | Отсутствует или null | Явно пустое |
| --- | --- | --- |
| `replacement` | нет предложения | `""` предлагает очистить черновик (Apply всё равно нужен) |
| `storage` | оставить значение | `""` сохраняет пустую строку (не удаляет) |
| `appearance` | оверлей не меняется | `{}` снимает оверлей плагина |
| `panel`, `effects` | `[]` | `[]` — нет элементов/предложений, а не «закрыть результат» |

Каждый возвращённый `appearance` **заменяет** предыдущий объект этого плагина (не патч); пропущенные поля темы наследуются от базовой темы. Опция сохранить выбор: храните его через `storage` и восстанавливайте при активации.

Элементы панели: `Text`, `Heading`, `Separator`, `Row` (вложенные дети), `Button`, `TextInput`, `Checkbox`, `Select`, `Slider`, а также `ActivityPreview` (превью кастомной активности). Лимиты: ≤64 элементов вместе с вложенными, ≤8 уровней вложенности рядов, текст и значения ≤4 КиБ каждый, ID элементов уникальны в панели.

### Предложения (effects)

Правила для всех действий хоста:

- `effects` разрешены только foreground-поверхностям `message`, `composer` и `panel`; `activation`, `message_event` и `app_event` вернуть их не могут.
- Не более одного предложения, ≤8 КиБ сериализованного массива; предложение нельзя совместить с не-null `replacement` в одном результате.
- Пользователь видит точную операцию и значения. Apply перепроверяет: плагин включён, capability выдана, аккаунт/разговор не сменились, разговор доступен, плюс проверки конкретной операции.
- Устаревшее предложение (stale) отклоняется, а не следует за навигацией.

Индекс операций:

| `type` | Capability | Операция |
| --- | --- | --- |
| `navigate` | `navigation` | Открыть известный канал |
| `home` | `navigation` | Вернуться в Friends/Home |
| `open_view` | `navigation` | Открыть нативный вид (18 значений `view`: `friends`, `search`, `pins`, `members`, `threads`, `settings`, `account`, `profile_settings`, `appearance`, `messaging_permissions`, `notifications`, `activity`, …) |
| `open_profile` | `navigation` | Открыть профиль известного пользователя |
| `jump_to_message` | `navigation` | Перейти к сообщению |
| `search` | `navigation` | Поиск в текущем разговоре |
| `open_external_link` *(Preview, вложен в `app_action`)* | `external_navigation` | Открыть проверенный HTTPS-URL |
| `notice` | `local_notices` | Локальный in-app toast |
| `copy_text` | `clipboard_write` | Записать текст в буфер обмена |
| `set_voice` | `voice_control` | Mute/deafen |
| `leave_voice` | `voice_control` | Покинуть звонок |
| `set_local_settings` | `local_settings` | Изменить настройки чтения |
| `set_notification_settings` | `notification_settings` | Изменить локальные настройки уведомлений |
| `app_action` | вложенное действие | Сообщения, треды, аккаунт, аудио и др. |
| `tracked_app_action` | грант вложенного действия + `action_feedback` | Получить результат допуска после Apply |

Примеры полных выходных объектов:

```json
{"effects":[{"type":"navigate","channel_id":"20"}]}
```

```json
{"effects":[{"type":"notice","text":"Review complete."}]}
```

```json
{"effects":[{"type":"app_action","action":{"type":"send_message","channel_id":"20","content":"Hello from my tool"}}]}
```

```json
{"effects":[{"type":"app_action","action":{"type":"set_reaction","channel_id":"20","message_id":"200","emoji":"👍","add":true}}]}
```

Все ID — строки десятичных цифр (ненулевые `u64`, ≤20 байт), не JSON-числа и не имена. Текст сообщений: непустой, ≤2000 символов и ≤8000 UTF-8 байт, и весь эффект ≤8 КиБ. `emoji` — Unicode-эмодзи или форма `name:id` для кастомных (имя 2–32 ASCII-символа, вся строка ≤128 байт).

`app_action` — типизированные операции через существующие нативные пути (полный список полей — в справочнике действий SDK проекта). Основные группы по грантам:

- **Сообщения** (`message_send`/`message_manage`/`reactions_control`): `send_message`, `send_reply` *(Preview)*, `send_sticker` *(Preview)*, `forward_message` *(Preview)*, `open_attachment_picker` *(Preview)*, `edit_message`, `delete_message` (необратимо), `set_message_pinned`, `set_reaction`, `mark_read`, `mark_channel_read`, `mark_unread`, `mark_guild_read`.
- **Треды/форум** (`threads_control`): `create_thread`, `create_forum_post`, `set_thread_archived/locked/followed/pinned`, `rename_thread`. Имена ≤100 символов/400 байт.
- **Каналы/серверы** (`channel_control`/`server_control`, Preview): mute/уведомления канала, создание/дублирование/правка/удаление/перемещение каналов, DM/группы, инвайты, настройки сервера, эмодзи, выход с сервера.
- **Роли/модерация** (`role_control`/`moderation_control`, Preview): CRUD ролей, выдача ролей, никнеймы, кик, prune, видимость списка участников.
- **Отношения/профиль** (`relationship_control`/`account_control`): DM с другом, никнейм друга, заметка, заявка/удаление друга, блокировка, свой профиль (имя/bio/pronouns/акцент), статус и кастом-статус, шаринг активности.
- **Аудио/звонки/камера/экран** (`audio_settings`/`voice_connect`/`voice_control`/`camera_control`/`media_control`): усиление/обработка/локальное воспроизведение участников и стрима, выбор устройств *(Preview)*, join/decline звонка, камера, выбор экрана *(Preview)*.
- **Запросы и редакторы** (`data_queries`, Preview): `request_message_search`, `request_pins`, `request_archives`, `request_member_search`, `request_profile`, `request_gifs`; результаты приходят в `ExtendedAppInvocation.queries` на следующем `app_event`.
- **Настройки/папки** (`messaging_settings`, `guild_folders`, Preview): патч приватности сообщений; полная замена раскладки папок с `base_version`.

Отслеживаемое действие с обратной связью:

```json
{"effects":[{"type":"tracked_app_action","request_id":"save-42","action":{"type":"set_activity_sharing","enabled":false}}]}
```

После Apply обработчик `app_event` получает `action_result` со статусом `accepted`/`rejected` и кодом `accepted`, `context_changed`, `unavailable`, `invalid`, `denied` или `failed`. Это допуск в нативный путь, а не гарантия успеха последующего сетевого запроса.

### События сообщений (`message_events`)

Объявите ≤1 действие с поверхностью `message_event` и capability `message_events`. События приходят только для активного доступного разговора и только для принятых хостом живых изменений: история, поиск, кэш и ephemeral не генерируют событий. Доставка **best effort**: очередь ≤32 вызовов / 64 КиБ, старт ≤10 событий в секунду, перегрузка — события отбрасываются; дубликаты create возможны не всегда и не являются «ровно один раз».

Поля события (`MessageEvent`):

| Поле | Тип | Смысл |
| --- | --- | --- |
| `kind` | `create` / `update` / `delete` | Тип события. |
| `channel_id` | string | Активный разговор. |
| `message_id` | string | Затронутое сообщение. |
| `author_id` | string, опц. | Обязателен для create; может отсутствовать у update; у delete всегда отсутствует. |
| `content` | string, опц. | Обязателен для create; у update — при текстовом патче; ≤16 КиБ UTF-8. У delete никогда. |

Обновление без `content` ничего не говорит о тексте; `"content": ""` — известный пустой текст. События не содержат вложений, embed'ов и сырых Gateway-данных.

```json
{
  "action": "on-message",
  "values": {},
  "message_event": {"kind": "update", "channel_id": "100", "message_id": "200", "content": ""}
}
```

Обработчик событий обязан вернуть пустые `panel` и `effects` (нельзя заменить черновик или открыть панель в фоне); отдельно выданные `storage` и `appearance` доступны. Показывайте результаты отдельным `panel`-действием. Полный пример счётчика (реальный пример проекта):

```rust
use axmatcord_extension_sdk::{Element, EventInvocation, MessageEventKind, Output};

fn handle(input: EventInvocation) -> Output {
    let count = match input.invocation.storage_json::<u64>() {
        Ok(value) => value.unwrap_or(0),
        Err(_) => return Output::default(),
    };
    if input.invocation.action == "on-message" {
        let mut output = Output::default();
        if input.message_event.as_ref().is_some_and(|event| {
            event.kind == MessageEventKind::Create
        }) && output.set_storage_json(&count.saturating_add(1)).is_err() {
            return Output::default();
        }
        return output;
    }
    if input.invocation.action == "show" && input.message_event.is_none() {
        return Output {
            panel: vec![Element::Text { text: format!("Delivered creates: {count}") }],
            ..Default::default()
        };
    }
    Output::default()
}

axmatcord_extension_sdk::export!(handle);
```

Манифест к нему: `capabilities: ["message_events", "storage"]`, действия `message_event` (id `message-event`), `show` и `reset` (обе — `panel`).

### События приложения (`app_events`)

Объявите ≤1 действие с поверхностью `app_event` и capability `app_events`. Базовые причины: `ready`, `navigation`, `connection`, `context`, `voice`, `settings`. С грантом `data_events` добавляются 15 детальных причин-«намёков на инвалидацию»: `account`, `channels`, `members`, `presence`, `read_state`, `message_details`, `relationships`, `threads`, `roles`, `permissions`, `recovered`, `reactions`, `pins`, `typing`, `polls` — каждой нужен свой грант чтения (например, `typing` требует `conversation_activity`, `polls` — `message_content`). Всего 21 имя.

Это **не** сырые сервисные события и не журнал изменений: однотипные причины объединяются, снапшот снимается при отправке вызова и может отражать несколько изменений. Обработчик события пассивен: без панели и effects; отдельно выданные `storage` и `appearance` доступны.

Пример полного входа `app_event` со снапшотом деталей канала:

```json
{
  "action": "on-app",
  "values": {},
  "app_event": "channels",
  "app": {
    "channel_details": {
      "channel": {"id": "100", "guild_id": "200", "name": "general", "kind": 0},
      "position": 0,
      "recipients": [],
      "recipients_truncated": false,
      "can_send": true,
      "can_read_history": false
    }
  }
}
```

### Снапшоты приложения (`AppSnapshot`)

Снапшот приходит в `input.app` для foreground-действий и `app_event`; активация и события сообщений снапшотов сейчас не получают. Каждая группа требует свою capability:

`context` (`app_context`), `account_profile`, `guilds` (`guild_directory`), `channel_details`, `channels` (`channel_directory`), `timeline`, `members`, `presence`, `voice` (`voice_state`), `read_state`, `settings` (`local_settings`), `notification_settings`, `audio_settings`, `own_presence` (`account_control`), `message_content`, `message_details`, `relationships`, `channel_metadata`, `member_details`, `forum_data`, `conversation_activity`.

Правила чтения снапшотов:

- Весь сериализованный снапшот ≤64 КиБ; у групп свои бюджеты (timeline 20 КиБ, channels 10 КиБ, guilds 8 КиБ, members/presence/получатели/метаданные/детали участников по 6 КиБ и т.д.). Список может упереться в байтовый бюджет раньше лимита элементов; усечённые списки помечаются `truncated`.
- **Отсутствующая группа** = данные не выданы или недоступны. Не считайте это «пустым списком». `"items": []` — группа есть, но подходящих строк нет.
- IDs — десятичные **строки** (например `"100"`), представляющие ненулевые `u64` ≤20 байт. Не JSON-числа: некоторые языки теряют точность больших ID. Сравнивайте и возвращайте их как строки.
- Отключение от Gateway убирает большинство групп; известный недоступный канал не показывается в группах выбранного канала.
- Никакой снапшот не содержит токены, удалённый/ephemeral текст, байты вложений, сырые медиа или неограниченное состояние клиента.

Публичное поле `host` (см. выше) доступно и без грантов — используйте его, чтобы писать один обработчик под несколько ревизий хоста.

## 8. Темы

Пакет темы — `.axmatcord-extension` JSON с манифестом `"kind": "theme"`, **без** capabilities/actions и **без** Wasm, плюс объект `theme`:

```json
{
  "manifest": {
    "api_version": 1,
    "id": "my-theme",
    "name": "My Theme",
    "version": "1.0.0",
    "author": "Your name",
    "license": "MIT",
    "source": "https://github.com/you/my-theme",
    "kind": "theme"
  },
  "theme": {
    "light": {"colors": {"accent": "#087F8C", "accent_text": "#FFFFFF"}},
    "dark": {"colors": {"chat": "#15252A", "accent": "#55CBD7", "accent_text": "#15252A"}},
    "style": {
      "body_size": 16,
      "icon_size": 20,
      "button_padding": [16, 8],
      "control_height": 36,
      "widget_radius": 2,
      "window_radius": 4,
      "menu_radius": 4
    }
  }
}
```

Тема переопределяет именованные цвета, нативную типографику, отступы и радиусы; плагин с `appearance` возвращает объект той же схемы. Тема **не может** переставлять панели, внедрять CSS/скрипты, загружать шрифты, тянуть URL картинок или менять данные сообщений.

Цвета: `#RRGGBB` или `#RRGGBBAA`. Токены:

| Область | Токены |
| --- | --- |
| Поверхности | `base`, `sidebar`, `chat`, `raised`, `hover`, `selected`, `border` |
| Текст | `text_strong`, `text`, `muted`, `link` |
| Действия и состояния | `accent`, `accent_text`, `positive`, `warning`, `danger` |
| Упоминания | `mention_bg`, `mention_text` |

`light` и `dark` принимают `colors`, опциональный `backdrop` (массив из двух цветов градиента) и опциональный `background`. Пропущенные цвета наследуются от встроенной темы; пользовательский accent имеет приоритет над темой.

`style` (обе темы, все поля опциональны, значения — целые логические пиксели):

| Поле | По умолчанию | Диапазон |
| --- | --- | --- |
| `transparency_blur` | `true` (требует opt-in в Appearance) | `true`/`false` |
| `transparency` | настройка Appearance | 0–100 |
| `blur` | настройка Appearance | 0–100 |
| `body_size` | 15 | 10–28 |
| `heading_size` | 20 | 12–40 |
| `button_size` | 14 | 10–28 |
| `icon_size` | 20 | 16–24 *(Preview)* |
| `small_size` | 12 | 10–28 |
| `monospace_size` | 14 | 10–28 |
| `item_spacing` | [8, 8] | каждая ось 0–24 |
| `button_padding` | [12, 6] | каждая ось 0–24 |
| `control_height` | 32 | 24–56 |
| `widget_radius` | 8 | 0–24 |
| `window_radius` | 12 | 0–24 |
| `menu_radius` | 12 | 0–24 |

Неизвестные поля и значения вне диапазона отклоняются до установки.

### Фон и обложки

Пакет темы может содержать `background_image` — JSON-массив байтов PNG/JPEG ≤2 МиБ (путей и удалённых URL нет). Настройки картинки задаются в `background` (для каждой из `light`/`dark`):

```json
{
  "background": {
    "opacity": 100, "fit": "cover", "target": "window",
    "sections": {
      "top_bar": 85, "server_list": 85, "channel_list": 85,
      "message_list": 75, "member_list": 85, "composer": 90
    }
  }
}
```

`opacity` — 0–100 (по умолчанию 25), `fit` — `cover`/`contain`, `target` — `chat` (область сообщений) или `window` (всё окно), `sections` — независимое покрытие поверхностей 0–100. Отдельное поле `cover_image` (PNG/JPEG ≤2 МиБ) задаёт обложку карточки в Настройках → Темы (кроп 16:9); на фон разговора не влияет. Лимит пакета 16 МиБ включает обе картинки.

### Как сделать и проверить тему

- Встроенный редактор: Настройки → Темы → **Create theme** (вкладки Basics/Background/Colors/Advanced, живое превью, кнопки Save/Export). Export выдаёт портативный `.axmatcord-extension`.
- Вручную: пакет темы — простой JSON (проверено по фактическим файлам тем и структуре загрузки). `pack.py` для тем не применяется — он упаковывает Wasm-плагины.
- Идентификаторы тем при разборе приводятся к нижнему регистру (`Golden-Theme` = `golden-theme`); прочие ограничения id (разделители пути, не-ASCII, зарезервированные имена) сохраняются. Идентификаторы плагинов и манифесты каталога — строго lowercase.
- Лимит: 8 установленных тем. `Ctrl+Shift+F12` — сброс community-тем. Удаление из каталога не деинсталлирует тему с устройства.
- Офлайн-проверка схемы: `cargo run --locked -p ui --example theme_api`.

Плагин с `appearance` возвращает такой же объект темы (пример: `{"appearance":{"dark":{"colors":{"accent":"#55CBD7"}}}}`). Preview-действия `tick` могут обновлять оверлей по расписанию хоста (минимум раз в 250 мс после завершения вызова, только когда worker простаивает): плагин получает `tick_ms`, хост плавно интерполирует hex-цвета между принятыми результатами. Тики запускаются только пока подписан и включён, после ошибки расписание паузится до disable/enable. Это поддержка палитр, а не внедрение кода в UI.

## 9. Как попасть в каталог

Каталог — `catalog.json`, который клиент читает из ветки `main` публичного репозитория проекта ([github.com/xHarmless2/AxmatCord](https://github.com/xHarmless2/AxmatCord)). Клиент скачивает **только байты пакетов** по закреплённым URL и проверяет каждый SHA-256 перед установкой; репозиторий он не клонирует и сборочные скрипты на машине пользователя не запускает. Пустой каталог валиден; локальный импорт позволяет разрабатывать до попадания в список.

### Формат записи

Файл каталога: `{"api_version": 1, "entries": [...]}` — до 256 записей, файл ≤1 МиБ. Запись:

```json
{
  "manifest": {
    "api_version": 1,
    "id": "hello-context",
    "name": "Hello Context",
    "version": "1.0.0",
    "author": "Your name",
    "license": "MIT",
    "source": "https://github.com/you/hello-context",
    "kind": "plugin",
    "capabilities": ["app_context"],
    "actions": [{"id": "show", "label": "Show current channel", "surface": "panel"}]
  },
  "description": "Показывает выбранный канал. (≤256 символов и ≤1024 UTF-8 байт, без управляющих символов)",
  "release_url": "https://example.org/releases/v1.0.0/hello-context.axmatcord-extension",
  "sha256": "64 шестнадцатеричных цифр — SHA-256 байтов пакета",
  "download_bytes": 123456,
  "source_commit": "40 или 64 hex-цифры — полный коммит в main",
  "preview": {
    "url": "https://example.org/releases/v1.0.0/hello-context.png",
    "sha256": "64 hex-цифр — SHA-256 превью",
    "download_bytes": 65432
  }
}
```

| Поле | Обязательное | Правила |
| --- | --- | --- |
| `manifest` | да | Манифест пакета (правила — раздел 3); обязан совпадать с манифестом внутри пакета. `source` — HTTPS без credentials. |
| `description` | нет (по умолчанию `""`) | ≤256 символов, ≤1024 UTF-8 байт, без управляющих символов. |
| `release_url` | да | HTTPS; закреплена за полным коммитом в `main` (неизменяемая ссылка на release/коммит). |
| `sha256` | да | 64 hex-цифры — хеш байтов пакета (не превью). |
| `download_bytes` | да | Точный размер пакета: >0 и ≤16 МиБ. |
| `source_commit` | да | Полный коммит (40 или 64 hex-цифры), к которому закреплены байты. |
| `preview` | нет | `url` (HTTPS), `sha256` (64 hex), `download_bytes` (>0 и ≤256 КиБ). PNG/JPEG; предпочтительно 16:9 — магазин сохраняет пропорции. |

Требования к превью: оригинальный или лицензированный скриншот темы/плагина в работе; URL закреплён за неизменяемым release или коммитом; точные размер и хеш. Превью описывают именно опубликованную версию, они созданы автором и **не** являются доказательством совместимости. Скачивание превью — без учётных данных, с 5-секундным дедлайном и проверкой хеша/размера; декодирование — до 256 КиБ сжатых, 4096 пикселей на сторону, ~4,2 млн пикселей и 32 МиБ бюджета декодера; миниатюры сжимаются до 640×360; отсутствующее/невалидное превью не блокирует установку. В репозитории превью обязано делить имя файла (file stem) с пакетом и весить ≤256 КиБ.

### Процесс публикации

1. Держите исходники и лицензию в публичном Git-репозитории. В манифесте `source` ведёт на него; эта ссылка отображается пользователям в Настройках.
2. Сохраняйте `manifest.id` между версиями; для любого изменённого пакета поднимайте `manifest.version`. Исходный и упакованный манифесты должны совпадать.
3. Пересоберите и перепакуйте плагин; при необходимости положите PNG-превью рядом с пакетом.
4. Откройте pull request, добавляющий пакет и воспроизводимые исходники/инструкции сборки в `extensions/` репозитория проекта. CI проверяет каждый пакет, манифест и превью (`python3 catalog.py --validate`), собирает плагины и прогоняет их через хост-песочницу. **Не** коммитьте изменения `catalog.json` в PR — он генерируется.
5. После слияния workflow закрепляет `catalog.json` за слитым коммитом (`catalog.py --pin`), записывая неизменяемые URL, длины и SHA-256. Запись появляется в клиенте только после закрепляющего коммита в `main`. Проверка локально: `python3 catalog.py --check`.
6. Мейнтейнеры ревьюят каждую версию, её capabilities и соответствие «исходники ↔ артефакт». Чек-сумма каталога идентифицирует проверенные байты — это **не** подпись и **не** гарантия безвредности кода. Обновления проходят то же ревью.

## 10. Ограничения ресурсов

Wasm исполняется на фоновом worker'е по требованию, с лимитами fuel/стека/памяти и без WASI/host-импортов; на каждый вызов — новый рантайм.

| Ресурс | Лимит | Что это значит для автора |
| --- | --- | --- |
| Скомпилированный Wasm | 4 МиБ | Держите модуль компактным; проверяются и импорты. |
| JSON-пакет | 16 МиБ | Манифест + закодированный payload + картинки темы. |
| Линейная память | 16 МиБ | Включая декодирование, аллокации обработчика и буферы вывода. |
| Execution fuel | 10 000 000 | Делится на парсинг и исполнение; вход корректного размера всё равно может исчерпать fuel. |
| Глубина вызовов / стек | 128 вызовов / 256 КиБ | Избегайте глубокой рекурсии. |
| Сериализованный вход и выход | по 256 КиБ | Считайте UTF-8 и JSON-escaping, включая вложенный storage-JSON. |
| Действия / capabilities манифеста | 16 / 64 | Только известные имена capabilities (сейчас 56). |
| Панель | 64 элемента / 8 уровней рядов | Текст и значения ≤4 КиБ каждый. |
| Хранилище плагина на диске | 1 МиБ | Практический размер ограничен и бюджетом вызова (256 КиБ). |
| Снапшот приложения | 64 КиБ | У групп свои меньшие бюджеты; списки могут быть усечены (`truncated`). |
| Предложения (effects) | 1 / 8 КиБ | Только foreground-действия; только после Apply. |
| Очередь событий | 32 вызова / 64 КиБ / 10 стартов в секунду | Реактивные события best effort; избыток отбрасывается. |
| Установленные плагины / темы | 8 / 8 | Девятый придётся сначала отключить. |

Невалидный вывод или исчерпание бюджетов даёт ошибку исполнения и может отключить плагин; усечённые списки и пропущенные события обрабатывайте в коде.

## 11. Wasm-ABI для языков, кроме Rust

Контракт буферов ABI v1 не привязан к Rust. Модуль обязан экспортировать:

| Экспорт | Контракт |
| --- | --- |
| `memory` | 32-битная линейная Wasm-память. Никаких WASI и function-импортов. |
| `axmatcord_alloc(i32 length) -> i32 pointer` | Выделить место под UTF-8 JSON-вход хоста. |
| `axmatcord_invoke(i32 pointer, i32 length) -> i64 output` | Вернуть UTF-8 JSON: указатель вывода в старших 32 битах, длина в байтах в младших. |

Каждый вызов получает свежий экземпляр; после завершения вызова он уничтожается вместе с ABI-буферами. Хост также принимает прежнюю пару `axmatds_alloc`/`axmatds_invoke` — пакеты, собранные до переименования, продолжают работать без пересборки; в новых модулях экспортируйте имена `axmatcord_*`. Обёртки Rust (`export!`) разворачиваются в те же плоские JSON-поля: на проводе нет ключей `invocation`/`output`, и Discord-IDs — десятичные строки, не числа.
